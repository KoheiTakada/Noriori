# 終電通知

家の最寄り駅へ帰れる最後の経路を調べ、今いる場所を出る期限の15分前に知らせる。通知するエリアの内側かつ通知しないエリアの外側で動く。

## 登録

| 項目 | 動き |
| --- | --- |
| 家の最寄り駅 | 1駅。検索候補の選択ですぐ保存。半径・地図の編集はない |
| 通知しないエリア | 1つの円。初期半径500mで最寄り駅に置く。位置と広さは別に編集できる。内側では終電を止める |
| 通知するエリア | 1つの円。内側だけ終電を通知し、外側では止める。駅を選ばず地図を動かして編集 |
| 通知のタイミング | 初期値は15分前。終電画面から変更できる |

家の最寄り駅は候補を選んだ時点で確定する。毎回の行き先選択や監視開始操作は求めない。

通知するエリアの初期半径は150km、編集範囲は100m〜1,000km。家の最寄り駅を初期の中心とし、地図の移動・ピンチ・スライダーで場所と広さを変える。中心となる駅や名前の入力はない。旅行先を個別に追加する操作は不要。宿泊先への終電検索は含めない。

2つの円は独立して保存する。最寄り駅を変更した場合は通知しない円の中心を新しい駅へ移し、設定した広さは保つ。同じ駅を選び直しても、移動した円の中心は戻さない。最寄り駅を削除した場合は通知しない円も削除する。

旧版の家は、その位置から同梱データの最寄り駅へ移行し、旧家の中心と広さを通知しない円として引き継ぐ。半径のない最寄り駅だけが保存されている場合は500mの円を補い、保存済みの経路・予約・通知する円を維持する。旧版の旅行先の円は反転して転用せず保管する。降車の駅・オンにする場所・通知の余裕も保持する。

## 通知時刻

終電は「家まで乗り継げる最後の経路」。最寄り駅の最終発車だけでは判断しない。

- 出発駅は周辺の複数候補から探す。帰宅先は登録した家の最寄り駅。
- 日本国内の電車・地下鉄と、前後の徒歩を対象にする。
- 追加料金が必要な新幹線・特急、バス、タクシーは初期検索に含めない。
- 最後まで乗り継げる経路のうち、現在地を最も遅く出られる経路を採用する。
- 駅までの徒歩、駅入口から乗り場までの移動、乗換時間を考慮する。APIの結果に含まれる時間を二重に引かない。

**ここを出る期限 = 最初の列車の発車時刻 − 駅までの徒歩 − 乗り場までの余裕**
**通知時刻 = ここを出る期限 − 15分**

乗り場までの時間を取得できない場合は、初期案として5分の余裕を置く。歩行時間や通知の余裕とは分けて扱う。

例：最終発車23:50、徒歩10分、乗り場まで5分なら、出発期限23:35・通知23:20。

## 自動更新

1. 家の最寄り駅の登録完了、家付近からの外出、通知するエリアへの進入、位置取得の復帰で検索する。23時を待たない。
2. 結果を取得した時点で通知を端末に予約する。通知時刻になってから検索を始めない。
3. 出発駅の候補や徒歩時間が変わる移動を検知したら、経路と予約時刻を更新する。同じ場所では結果を再利用する。
4. 通知前に位置・経路の更新を試みる。更新できなくても予約済みの通知を勝手に捨てない。
5. 通知しないエリアに入った、または通知するエリアの外に出たことが確定したら、予約・鳴動中の終電通知・検索・高頻度の測位を止める。
6. 通知するエリアへ戻ったら、同じ夜の停止操作がなければ検索を再開する。

精度の低い測位1回で範囲の内外を確定しない。位置の精度範囲まで円内なら進入、円外なら退出を確定し、境界が不明な間は直前の判定を維持する。通知しない円の内側では停止を優先する。その境界が不明でも、通知する円の外にいると確定できる場合は止める。固定の駅付近の判定は使わない。

時刻表の運行日と実際の日時を別に管理する。0時で夜の監視を切らず、翌朝の始発を「まだ乗れる終電」として採用しない。初めて位置を取得した時刻が0時以降でも、前後の運行日を確認して、その夜の終電を選ぶ。

## 通知と停止

- 降車・終電の警報は、1.2秒ごとに同じ通知IDで上書きし、1回1秒の有限の振動を鳴らす。通知欄の件数を増やさず、スワイプ後も再表示する。「停止」で通知・振動・再送をまとめて解除する。
- 表示は「ここを出る時刻」、乗る駅、家までの経路に絞る。位置が古い場合は、その測位時刻を添える。
- 停止すると終電通知を消し、その夜の追加通知も止める。再検索やアプリの再起動で鳴らし直さない。
- 翌運行日、または家への帰宅を確認してから再外出したときに再開する。0時だけでは再開しない。
- すでに帰宅中なら、終電画面から任意で「今夜はオフ」にできる。毎回の必須操作にはしない。
- 移動速度や家に近づいていることだけで「帰宅中」と決めて通知を止めない。
- 降車通知と重なったら振動を一本化し、降車を優先して表示する。通知原因は独立して保持し、停止時点の鳴動中通知をまとめて消す。駅の自動オン条件は維持する。

地下では帰宅中・乗車済みを確実に判定できない。自動停止を優先すると帰り忘れを取り逃がすため、初期実装では通知が重なる可能性を許容する。

## 例外

| 状況 | 動き |
| --- | --- |
| 終電が22時台 | 外出時点で検索し、算出した通知時刻に鳴らす |
| 23時以降も外出中 | その夜の終電を検索・更新する |
| 通知予定を過ぎたが、出発期限には間に合う | まだ通知していなければ即時に鳴らす |
| 出発期限を過ぎ、間に合う経路がないことを確認できた | 「間に合う終電なし」を一度だけ通常通知。振動の連続警報は始めない |
| 終電が0時以降 | 前夜から同じ予約を引き継ぐ |
| 通知するエリアの外・通知しないエリアの中 | 通知を止める。2つの円が重なる場所も通知しない |
| 徒歩だけで帰れる経路が、標準の徒歩検索条件で成立する | 終電通知は不要 |
| GPSが途切れた・予約あり | 最後に確認した場所からの予約を維持する。帰宅したと推測して消さない |
| GPSが途切れた・予約なし | 終電を確認できないと表示。位置復帰時に検索し、通知予定を過ぎていれば即時判定する |
| API失敗・通信切断 | 同じ運行日・出発地点に対する有効な保存結果があれば予約を維持する。結果がなければ「終電を確認できない」 |
| APIの検索結果が空 | 「終電を過ぎた」と即断しない。確認できない状態と、時刻判明後の期限超過を分ける |
| 予約後に期限が早まる | 予約を前倒しする。通知予定が過ぎていれば即時に鳴らす。停止済みなら鳴らし直さない |
| 予約後に期限が遅くなる | 予約を更新する。鳴動中・停止済みの通知を新たに繰り返さない |
| 端末再起動・アプリ更新 | 保存した経路、予約、停止済みの状態を復元する |
| 時計・タイムゾーンの変更 | 経路の実時刻から予約を組み直す。端末の日付だけで運行日を切り替えない |

位置・経路の取得失敗は終電画面内にだけ表示し、プッシュ通知を出さない。地下からの測位復帰、通信の再接続、検索の失敗と成功の繰り返しでも通知を増やさない。保存済みの経路と予約は従来どおり維持し、バックグラウンドで再試行する。次の検索成功で画面内の取得エラーを解除する。旧版が出した「終電を確認できない」通知は更新・起動時に消す。

遅延・運休情報が取得できた場合は再計算する。時刻表だけの結果を、列車の運行確認済みとは扱わない。

## 画面

| 画面幅 | 機能の切り替え |
| --- | --- |
| コンパクト | 下部タブ「降車」「終電」 |
| 広い画面 | 物理的な右端の下部にサイドバーを固定。同じ2機能を表示 |

折りたたみ端末でも、分割画面なら表示幅に合わせる。展開・折りたたみで選択中の機能、地図、編集中の場所を失わない。ヒンジに操作を重ねない。

- 降車画面は既存の駅・オンエリアを維持する。
- 終電画面には、出発期限のカードと「家の最寄り駅」「通知しないエリア」「通知するエリア」を置く。
- 家は駅候補の選択だけで保存する。2つのエリアは地図・円で編集し、距離の数値入力は求めない。通知しない円はグレー、通知する円は青で描く。
- 機能の説明、保護中の大きな表示、全体設定画面は追加しない。
- 必要な権限案内と、期限を出せない理由だけは省略しない。
- アイコンには読み上げ名を付ける。時刻・オンオフは色だけに依存させない。
- 実画面のデザインは、現行サービスのUI画像を確認してから既存デザインシステムに組み込む。

## 実装で確定したもの

**経路データ**：ユーザー指定の [Transit API](https://api.transit.ls8h.com/) を使用する。認証なしの公開APIで、運行日・終電・乗継・前後の徒歩を構造化して取得する。現在地と家の最寄り駅の座標を検索時に送る。APIキー入力や契約操作は不要。

終電検索に翌朝の始発待ちが混ざる場合は、同じ夜の到着上限を指定して再検索する。運行日を日本時間04:00で区切り、翌朝まで待つ経路を採用しない。30分を超える徒歩だけの代替は通知を消す根拠にしない。時刻表が古いデータや平均頻度だけのデータは予約に使わない。取得結果の出典を画面から確認できる。

**端末の予約**：取得結果から端末の正確なアラームを予約し、画面を閉じても通知する。必要な「アラームとリマインダー」の許可を終電画面で案内する。拒否・取り消し時は許可が必要と表示する。予約と停止済み状態を保存し、再起動・更新後に復元する。

**操作**：コンパクト画面の操作は下部に集める。駅の保存時にオンにする場所がなければ、そのタブへ進める。円のタップで編集先を切り替える。通知する駅の新規円は直径250m。既存の円の設定は保つ。

- [Transit API：仕様](https://api.transit.ls8h.com/api/openapi.json)
- [Android：アラームの予約と権限](https://developer.android.com/develop/background-work/services/alarms)

## 受け入れ確認

- [ ] 同じ場所で、22時台・23時台・翌0時台の終電をそれぞれ正しい実日時に予約できる
- [ ] 日付変更で予約を翌夜へずらしたり、停止済み通知を復活させたりしない
- [ ] 遠い駅の方が遅く家に帰れる場合も、徒歩込みで比較できる
- [ ] 最初の列車には間に合っても、最後の乗換に間に合わない経路を除外できる
- [ ] 通知予定後の初回測位で、出発期限前なら即時通知できる
- [ ] 通知するエリアからの退出で予約・鳴動を止め、進入で再計算できる
- [ ] 家の最寄り駅は半径なしで保存でき、2つのエリアの位置と広さを別々に編集できる
- [ ] GPS未取得から突然エリア内に現れても、確認した場所に応じて判定できる
- [ ] GPS・通信の途絶で、有効な予約を失わない
- [ ] API失敗を終電なしと表示しない
- [ ] 停止後に再検索・再起動しても鳴らし直さない
- [ ] 翌運行日と、帰宅後の再外出で再開できる
- [ ] 画面オフ・省電力・再起動後に、予約時刻の通知を実機で確認できる
- [ ] 通知を停止すると通知センターから消える
- [ ] 既存の降車通知と同時発生しても、二重振動・通知の上書きを起こさない
- [ ] 保存済みの駅・オンエリアを変更しない
- [ ] 折りたたみ・展開・分割画面で編集内容を維持できる


## 動かす時間

終電の測位・経路検索・再試行は日本時間18:00〜翌04:00だけ行う。04:00〜18:00は位置サービス・ジオフェンス・取得ジョブ・警報予約を解除し、18:00の再開予約だけ残す。画面を開いても朝昼の終電検索を始めない。18:00の再開・04:00の停止を、再起動や時計の変更でも復元する。降車の監視は別に継続する。

夜の経路取得はバックグラウンドのジョブで行う。「終電を確認中」の常駐通知は出発期限の2時間前から。出発期限または04:00に確認を終了する。検索成功時は画面の取得エラーを消す。通知は出発期限の15分前が初期値。

## 近くの駅から乗る経路

駅への徒歩・降りてからの徒歩・電車間の徒歩は、それぞれ15分以内に限る。池袋まで徒歩で移動するなどの長い徒歩で、必要な電車の経路を置き換えない。

座標からの検索で適切な経路が得られない場合、同梱の駅データから近い3駅を探し、APIの駅IDと座標で照合して、その駅から家の最寄り駅までの経路を調べる。駅名が同じ別地域の駅やバス停を出発駅にしない。翌04:00前の到着検索で翌朝の始発待ちを除き、徒歩込みでいちばん遅く出られる経路を選ぶ。

駅IDから検索する場合のアクセス徒歩は、現在地から駅までの球面距離に35%の迂回を見込み、秒速1.2mで推定する。道路や駅入口の実際の歩行経路ではない。5分の乗り場の余裕を別に引き、通知の余裕をさらに引く。APIの徒歩時間を使う経路は二重に引かない。

制限のない旧経路キャッシュは更新後に使わない。駅・家の最寄り駅・円・通知の余裕は保存したまま引き継ぐ。

## 午前4時の全オフ

日本時間の午前4時に全駅のオン状態・降車と終電の警報・通知・再送・予約を解除する。駅・円・通知の余裕は残す。次のオンエリア進入または手動オンから、通常の動作を再開する。新しい設定画面は追加しない。

終電の家がなくても毎日のリセットを予約する。正確なアラームの許可がない場合は省電力中に動かせる予約へ切り替える。鳴動中の再送処理でも4時を確認する。再起動や時刻変更後は予約を組み直し、未実行の境界を越えていれば古い状態を解除する。同じリセットを再受信しても、その朝に新しくオンにした状態を消さない。

警報を出している間だけ画面オフ中の再送に必要なCPUの起動状態を保つ。停止・全オフ・サービス終了でタイマーと起動状態の保持を解除する。通知を表示できない場合は警報中の状態も解除する。
